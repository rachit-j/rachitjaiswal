# Design system

## Direction

The site uses a technical-editorial language: research-lab clarity, engineering-notebook metadata, and restrained product-level polish. Typography, grids, material, and documentation carry the personality.

## Tokens and themes

- Define tokens for background, surface, text, muted text, accent, border, spacing, type scale, content widths, grid, radii, motion duration, easing, and z-index.
- Follow `prefers-color-scheme` with paired ink/paper themes. Both themes use high contrast, thin rules, and one muted accent; no manual theme selector is needed.
- Use Instrument Sans for display/body hierarchy and IBM Plex Mono for technical metadata, dates, taxonomy, and compact controls.

## Composition

- Use 4-column mobile, 6-column tablet, and 12-column desktop grids with intentional asymmetry only where it improves hierarchy.
- Hero uses oversized static name/thesis, short technical taxonomy, and a measured rule/metadata treatment; identity text never rotates.
- Use generous vertical rhythm, reading-width prose, explicit image ratios, and understated metadata. Real project materials carry visual weight when available.
- Project cards are editorial modules, not a wall of rounded panels; archive rows are compact and scannable.

## Interaction

- Links/buttons use clear text/rule/arrow affordances and visible focus. Default controls have 44px touch targets.
- Borders are fine and structural; radii are small and sparingly used.
- Hover response is limited to small image scale, arrow offset, metadata contrast, or rule movement over 180–350ms.

## Exclusions

No particle fields, WebGL, cursor effects, terminal simulations, dashboard widgets, glowing boxes, glass-card UI, neon/cyberpunk styling, gradient blobs, generic technology-logo decoration, or every-section-is-a-card treatment.
